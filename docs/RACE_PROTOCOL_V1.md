# RACE Protocol v1

RACE is a platform-neutral timing system used by the Android app, the future iOS app, Rider Control Center, and the large-screen LIVE display.

## Identity

Public profile input is intentionally limited to **name** and **nickname**. A hidden `profile_id` is generated by the app. An event join creates a server-side participant identity/token; users never type that internal ID.

## State machine

`STOPPED -> ARMED -> RUNNING -> FINISHED`

- Entering a course while STOPPED never records a race.
- The rider must intentionally press START to enter ARMED.
- Official timing starts only when the oriented START gate is crossed in the correct direction.
- Sector/Split gates and FINISH use the same oriented-line crossing rule and interpolate crossing time between adjacent GNSS samples.
- FINISH is saved locally before network upload.
- A later START creates the next Run number for the same event.

## Raw evidence vs derived data

Raw GNSS is journaled independently. Course progress, gates, sectors, splits, delta and validity are derived. This allows later re-processing when course/gate definitions are corrected.

## Course matching

The GPX centerline is converted to one-dimensional course progress in metres. After the initial match, matching searches a physically plausible window around the previous progress instead of the entire GPX, preventing jumps across nearby switchbacks/folded trails.

## Timing and sectors

Each completed Run contains:

- total elapsed milliseconds
- Sector times
- cumulative Split times
- reduced distance/time reference trace
- max speed
- GPS accuracy/off-route quality metrics
- VALID / REVIEW / INVALID status
- stable `run_id` for idempotent upload

Leaderboards count the best valid Run per participant. Sector leaderboards are independent from the overall leaderboard. Theoretical Optimal is analysis-only and is the sum of best sectors.

## LIVE

During RUNNING, the phone may send an ephemeral ~1 Hz packet containing participant/run, course progress, elapsed time, current sector, speed, GPS accuracy and current leader delta. LIVE packets are not the official record and are not written to the database every second.

START, Sector and FINISH are durable events. Sector/FINISH uploads are queued if offline and retried. The public broadcast display shows current rider, live leader gap, estimated rank, progress, sector ranks, overall leaderboard and finish result.

## Cross-platform contract

Android and iOS must use the same field meanings, interpolation rules, gate direction, millisecond rounding, validation states and API payloads. The same replay log should produce the same total/Sector/Split result on both platforms.

## Location sources

The timing core must not assume phone GNSS forever. Location source is abstracted conceptually so later builds can add external 5/10/25 Hz GNSS without changing server or race-result formats.
